# Cursor 用量：由 ~90% 退返 ~60% 係點解？

查詢日期：2026-08-29  
帳號（呢次 Cloud Agent run 擁有者）：Shane Kwok / skwo671@gmail.com

## 重要

呢個 Agent **睇唔到** 你 Dashboard 入面嘅實時剩餘用量／billing 數字。  
要自己開：https://cursor.com/dashboard/spending

Spending 會顯示：兩個用量池、剩除 allowance、on-demand 收費、同 **reset date**。

## 錶通常代表咩

多數 plan 有 **兩個獨立每月用量池**：

1. **Cursor Models**（Grok 4.6 / 4.5、Composer 2.5）
2. **Other Models**（第三方 model，跟 API 價）

Dashboard 嘅 % 多數係 **已用咗幾多 included quota**（越接近 100% 就越用完），唔係「剩低幾多 %」。

## 點解會由九十幾「退」返六十幾

官方文件寫到嘅常見原因：

1. **Billing cycle reset**（最常見）  
   用量跟你訂閱嘅每月週期清零；未用完 **唔會** 滾存。Reset date 喺 Spending tab。

2. **升級 plan**  
   配額即時加大，同樣絕對用量會顯示成更低嘅已用 %。

3. **睇錯／睇咗另一個 pool**  
   Cursor Models 同 Other Models 分開計；Auto/Router 可能兩邊都食。一個池 90、另一個 60，會以為「退咗」。

4. **Included 用完轉 on-demand**  
   included 到頂之後，再係 on-demand 計，唔會永遠推高同一個 included %。

一般情況下，**正常傾偈／Agent 用唔會中途「退還」已用 %**。若無 reset、無升級、無換 pool 顯示，先至值得當異常。

## 建議你即刻對呢幾樣

- 開 [Spending](https://cursor.com/dashboard/spending)，睇 **reset date** 同兩個 pool 各自 %  
- 對吓「退返 60」嗰日係咪啱正 reset／改 plan  
- Billing：https://cursor.com/dashboard/billing
